Each user on this server gets a private watchlist, held on the server and readable by nobody else. Once the projection is built it appears in every client as a playlist owned by that user, so no client has to be changed, and adding or removing an item there is the same as adding or removing it from the list.

Nothing appears in a client today. What is built is the store the lists are kept in; the playlist projection and the endpoints are not, which is why no release is published. The settings below are the whole set this plugin will have, saved and kept from now on, and the ones that drive the projection are read by nothing until it lands. This paragraph is the answer to the first question an administrator asks after installing this, and it changes when the projection lands rather than before.

No value here is refused yet. A number outside its range or an empty name is stored as typed, and refusing it at save time is a change still to come.

The private list

On by default. The projection is this plugin's whole client surface, so turning it off leaves the lists held on the server and shown nowhere. Nothing stored is deleted by turning it off.
The name of the playlist a user sees. It is deliberately not the bare word "Watchlist": a server may grow a watchlist of its own, and two lists under one name in one client is a thing a user cannot resolve by looking, because a playlist does not say what created it.
An add that would take a list past this is refused and nothing is written. Lowering it under a list that is already larger removes nothing: that list stops growing and says why. Ten thousand by default, which sits far above any list somebody curates by hand.
Off by default. A list somebody curated losing entries without being asked is a surprise, and nothing records what was taken off, so there is no undo. It never touches the shared list.
The scheduled pass exists to converge what the server's own events missed, not to be how lists are kept current, so six hours is the default. A pass over lists that are already correct writes nothing.

The shared list

Off by default. Every user on this server can read it and add to it, and an entry shows who put it there, so what somebody adds is attributable to them in front of everybody. There is one such list, not several.
The same naming rule as the private list, and it matters more here: one name is met by everybody on the server rather than by one person. The name is kept when the list is switched off, so switching it back on does not lose it.
Bounded separately from a private list because everybody writes to it, so the number of people who can grow it is the number of people on this server. It behaves the same way at the bound: an add past it is refused and nothing is written.
